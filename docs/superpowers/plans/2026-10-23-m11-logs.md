# M11 Logs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An operator opens the logs of a service on a server (Redis, Kafka, nginx, Node.js, or the system journal) and watches new lines arrive in the browser. Secrets and personal data are masked on the host before any line leaves it, and nothing is stored. Each monitored service also shows error, OOM, and stack-trace counts as metrics, with charts.

**Architecture:**
- **Live tail.** The browser opens an SSE stream at `GET /api/v1/agents/:id/logs/tail?source=…`.
  - **API side:** the API checks `logs.tail` and the per-tenant limit, creates a signed `log_tail` task and a stream session, and relays `stream:<session>` Redis messages as SSE events. When the browser disconnects, the API closes the session.
- **Agent side.** The agent checks the source against its own allowlist, which is computed from the packs it has applied plus the host journal. It follows the file (or `journalctl -f`), redacts each line, and posts chunks at a capped rate. It stops when the session is closed (the next chunk gets 404), the TTL expires (15 min), or the task runtime runs out.
- **Log-derived metrics.** The collector reads the enabled packs' log files with `filelog`, tags each line with `service` and `level` (plus `pattern` for OOM and stack traces), and the `count` connector turns them into `log_lines_total{service,level}` and `log_pattern_total{service,pattern}` over remote_write.

**Tech Stack:** Go 1.23 (agent), OpenTelemetry Collector v0.162.0 `filelogreceiver` and `countconnector`, NestJS 11 SSE (Fastify raw reply), ioredis pub/sub, Next.js 15 `EventSource`, Recharts.

**Spec:** spec §11.8, §18.2; master plan M11.1–M11.2, §3 live tail limits; WB-12 UC-12-01..03.

**Deferred:**
- Retained logs and search (VictoriaLogs, M18.1).
- Data inspection (M18.2).
- Docker stdout sources (need a socket proxy).
- PM2 log paths under user home directories: they are configured per app, so they are not auto-discovered.
- The default "error-rate spike" alert rule, which comes with M12 alerting. The metric ships here.

## Global Constraints

- **Allowlisted sources only.** Only sources the agent allows can be tailed: the applied packs' `logSources` plus `host.journal`. A path is never taken from the request; only a source ID is (WB-12).
- **Redaction on the host** before lines leave it (UC-12-02):

  | Match | Replacement |
  |---|---|
  | Bearer and `Authorization:` header values | `Authorization: [REDACTED]` |
  | JWTs | `[JWT]` |
  | `ghp_` / `github_pat_` / `sk-` / `sk_live_` / `xox?-` / `AKIA…` tokens | `[TOKEN]` |
  | `password=`, `secret:`, `api_key=`, `token=` values | `[REDACTED]` |
  | Email addresses | `[EMAIL]` |
  | Luhn-valid 13–19 digit card numbers (spaces or dashes allowed) | `[CARD]` |
  | URL credentials | `user:[REDACTED]@` |
- **Limits (master plan §3):**
  - at most 200 lines/s per stream; excess lines are dropped and counted, with a "dropped N lines" marker
  - lines truncated to 4 KB
  - a 15-minute TTL per stream
  - at most 5 concurrent streams per tenant, and 2 per agent
- **Nothing stored.** The relay is Redis pub/sub only; no log line is persisted.
- **Permissions.** Live tail needs `logs.tail` (operator, admin, owner). Listing sources needs `agent.view`.

## Review Focus

1. **A request names a path** (`/etc/shadow`), **a source the agent has not enabled**, or a traversal. Expected: the API refuses unknown source IDs (400) and the agent refuses anything outside its allowlist (failed task). A path is never accepted. Covered in Tasks 2 and 3.
2. **Secrets in log lines.** Expected: the full corpus is masked before posting, including a password inside a URL and a card number with spaces, and normal numbers are left alone. Covered in Task 1.
3. **The browser closes the tab.** Expected: the session closes, the agent stops within one chunk interval, and the tenant's concurrent count is released. A crashed API instance also releases the count by TTL. Covered in Tasks 2 and 3.
4. **A noisy service writes 10,000 lines per second.** Expected: at most 200 lines/s are sent, the rest are reported as dropped, and the agent's memory stays bounded. Covered in Task 2.
5. **Log rotation (file truncated or replaced) while tailing.** Expected: the tail continues from the new file, with no crash and no re-sent history. Covered in Task 2.

### Task 2: Agent log tail

**Files:** `internal/logs/{sources,tail,stream}.go` + tests, run-loop wiring in `cmd/pcp-agentctl` (`log_tail` handled concurrently), and the installer (`pcp-agent` joins `adm` and `systemd-journal` when they exist, for read access only).

**Interfaces:**
- `Sources(packs []collector.PackConfig) []Source`, where `Source{ID, Label, Kind: file|journal, Paths []string, Unit string}`.

  | Pack | Sources |
  |---|---|
  | `redis` | `redis.server`: `/var/log/redis/redis-server.log`, journal unit `redis-server` |
  | `postgresql` | `postgresql.main`: `/var/log/postgresql/postgresql-*-main.log` |
  | `mysql` | `mysql.error`: `/var/log/mysql/error.log` |
  | `mongodb` | `mongodb.main`: `/var/log/mongodb/mongod.log` |
  | `kafka` | `kafka.server`: `$KAFKA_HOME/logs/server.log` or `/opt/kafka/logs/server.log` |
  | `nginx` | `nginx.access` and `nginx.error`: `/var/log/nginx/*.log` |
  | `nodejs` | `nodejs.journal`: journal for units matching `node` |
  | always | `host.journal`: system journal |

  The first path that exists wins, and globs are resolved.
- `Tail(ctx, src Source, out func([]string) error, opts{Rate: 200, Flush: 500 ms})` follows from the end of the file and handles rotation (inode change or size shrink). For journal sources it runs `journalctl -f -n 0 -o cat [-u unit]`. Every line passes through `Redact`.
- **`log_tail` handler:** payload `{ source, sessionId }`. The source must be in `Sources(appliedPacks)`, otherwise the task is reported as failed with "source not allowed". It posts chunks `{sessionId, sequence, lines, final, sentAt}`. It stops on a 404 from the chunk endpoint (session closed), on context cancel, or at `maxRuntimeSeconds`. It sends a final chunk, then the task result.

  - rotation by rename then create, and by truncate
  - a source outside the allowlist is refused
  - a 404 from the chunk endpoint stops the tail
  - the journal command line is built without shell interpolation

  Implement, pass, write handoff `M11-agent-tail.md`, commit.

### Task 3: API live tail (SSE) and sources

**Files:** `apps/api/src/modules/logs/{logs.module,logs.controller,tail.service,sources}.ts` + `logs.int.test.ts`, and OpenAPI.

**Interfaces:**
- `GET /api/v1/agents/:id/log-sources` (`agent.view`) returns `{ sources: [{ id, label }] }`, computed from the agent's applied pack assignments plus `host.journal`. The Go table is mirrored in TypeScript, and a test pins both to the same IDs through a shared JSON fixture.
- `GET /api/v1/agents/:id/logs/tail?source=<id>` (`logs.tail`), served as `text/event-stream`:
  1. An unknown or not-enabled source gets 400.
  2. More than 5 streams for the tenant or 2 for the agent gets 429.
  3. Otherwise the API creates a `log_tail` task (TTL 15 min, `maxRuntimeSeconds` 900) and opens the stream session.
  4. It subscribes to `stream:<session>` and sends `event: lines` with `{ lines, sequence }`, `event: end` on a final chunk, and a heartbeat comment every 15 s.
  5. On client close it marks the session closed and releases the limit counters. The counters are Redis keys with a TTL, so a crashed instance cannot leak them.

- [ ] Failing tests:
  - SSE delivers published chunks
  - closing the connection marks the session closed, and a chunk for a closed session gets 404
  - a viewer gets 404
  - an unknown source gets 400
  - the 6th stream for a tenant gets 429
  - the task payload carries the source ID only (no path)

  Implement, pass, write handoff `M11-live-tail-api.md`, commit.

### Task 4: Log-derived metrics in the collector

**Files:** `internal/collector/{config.go,packs.go,logs.go}` + tests, `collector/builder-config.yaml` (`filelogreceiver`, `countconnector` v0.162.0), API service-chart templates (`errors per minute` for each pack), and the real-collector validation test.

**Interfaces:**
- **Receivers.** For each applied pack with file sources, a `filelog/<pack>` receiver with `include` set to the pack paths and `start_at: end`. Its operators:
  - add `attributes.service = <pack>`
  - a regex sets `attributes.level` to `error`, `warn`, or `info` (default `info`)
  - a router adds `attributes.pattern = oom` for `(?i)out of memory|oom-killer|OOMKilled`, or `stacktrace` for lines starting with whitespace followed by `at ` or for `Traceback`
- **Pipelines.** A `logs` pipeline runs from the `filelog/*` receivers through `memory_limiter` to the `count` exporter; the `count` connector is then a receiver of the metrics pipeline.
  - `count` defines `log.lines` (attributes `service`, `level`) and `log.pattern` (condition: `pattern` is set; attributes `service`, `pattern`).
  - The allowlist filter keeps `log` metrics.
- **Charts.** Service charts gain "Log errors per minute": `sum(rate({__name__=~"log_lines(_total)?",service="<pack>",level="error"}[5m])) * 60`.

- [ ] Failing tests:
  - the config for redis and nginx has filelog receivers with these operators, the logs pipeline, `count` in both pipelines, and the allowlist includes `log`
  - with no file sources there is no logs pipeline
  - `pcp-otelcol validate` passes for every pack once the collector is rebuilt (gated test)
  - the API template exists for each pack

  Implement, pass, write handoff `M11-log-metrics.md`, commit.

### Task 5: Log viewer UI

**Files:** `apps/web/components/logs/{log-viewer,log-sources}.tsx` + tests, host page integration (a "Logs" button per monitored service plus "System journal"), and the error-rate chart through the service templates.

**Behavior:**
- **Viewer.** The viewer opens an `EventSource` to the tail URL. Its controls:
  - live and ended states, plus an error state with a reason

  - shows "dropped N lines" markers
  - a note: "Masked on the server before sending; nothing is stored"
- **Lifecycle.** Closing the panel closes the `EventSource`, which ends the stream on the server.
- **Permissions.** Without `logs.tail`, the button is not shown.

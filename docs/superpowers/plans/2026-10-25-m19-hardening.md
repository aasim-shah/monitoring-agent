# M19 Hardening (production-critical subset) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make the running deployment recoverable and safer: nightly verified backups with a restore drill, browser security headers, a dependency audit, an independent watchdog, and tenant export and deletion.

**Architecture:**
- Backups and the watchdog are host scripts run by systemd timers on the VPS. They are additive and touch nothing else on the shared host.
- Security headers come from the Next.js app itself, so they hold behind any proxy.
- Tenant export and deletion are API endpoints plus worker jobs.

**Spec:** spec §17, §19, §11.13; master plan M19.1, M19.3, M19.5, M19.8; WB-17.

## Global Constraints

- **Shared VPS:**
  - New files only under `/opt/pcp` and `/etc/systemd/system/pcp-*`.
  - Never `docker * prune`.
  - Memory caps on any temporary container.
- **Backups:**
  - Run nightly. `pg_dump -Fc`, checked with `pg_restore --list` before being kept.
  - Keep 14 days.
  - Refuse to run when less than 1 GB of disk is free; say so instead of filling the disk.
  - Back up `.env` too: it holds the master key, without which stored credentials cannot be decrypted. Mode 600.
- **Watchdog:**
  - Alerts through SMTP directly, never through the platform's own worker (spec §11.13: an independent channel).
  - One email when a check fails, one when it recovers.

## Review Focus

1. A failed or truncated dump must never replace a good one, and must never delete older dumps.
2. The restore drill must not touch the production database or network.
3. The CSP must not break Next.js hydration, Google sign-in, or SSE live tail.
4. Tenant deletion must remove rows from every tenant table and leave other tenants untouched.
5. A tenant export must contain no secret material.

### Task 1: Nightly backup and restore drill

- **Scripts:**
  - `infrastructure/scripts/backup.sh` and `infrastructure/scripts/restore-drill.sh`
  - `infrastructure/systemd/pcp-backup.{service,timer}`
- **Test:** `tests/smoke/backup.test.ts`, against a throwaway Postgres container:
  - a good backup is kept and verified
  - a failing `pg_dump` leaves no new file and deletes nothing
  - files past retention are removed
  - the drill restores into a separate container and prints the row counts

### Task 2: Security headers

- **In `apps/web/next.config` `headers()`:**
  - CSP: `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; font-src 'self' data:; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'`
  - Referrer-Policy `strict-origin-when-cross-origin`
  - Permissions-Policy `camera=(), microphone=(), geolocation=(), payment=()`
  - X-Content-Type-Options `nosniff`
- **Tests:** a web unit test on the header list, and a smoke check against the live Compose stack.

### Task 3: Dependency audit

- Run `pnpm audit --prod`. Fix or rule on every high and critical finding.
- Add a repo test that fails on new high or critical findings, with an allowlist file for ruled exceptions.

### Task 4: Independent watchdog

- **Files:** `infrastructure/monitoring/watchdog.sh` and `pcp-watchdog.{service,timer}` (every 2 minutes).
- **Checks:** the API `/healthz`, worker readiness, the VictoriaMetrics health endpoint, and backup age (under 26 hours).
- **State:** in `/opt/pcp/watchdog/`.
- **Test:** a shell-level test with a fake mailer covers a failure (one mail), the same failure again (no mail), and a recovery (one mail).

### Task 5: Tenant export and deletion (WB-17 UC-17-09)

- **`POST /api/v1/organizations/:id/export`** (owner only):
  - A worker job builds a JSON archive of the tenant's rows, with no secret columns.
  - The download link is valid for 24 hours.
- **`POST /api/v1/organizations/:id/deletion`** (owner only, with MFA):
  - The organization enters `pending_deletion` for 30 days. Members lose access, agents are revoked, and connections are disconnected.
  - Cancelling within the 30 days restores access.
- **Purge job:** after 30 days, deletes every tenant-table row, crypto-shreds secrets, and deletes VictoriaMetrics series for the tenant.
- **Tests:**
  - the export contains no secret fixture
  - after a purge, no tenant table has a row for the organization, and another tenant is untouched
  - cancel restores access

### Task 6: Deploy and docs

- Deploy the web image and the host timers on the VPS.
- Run the restore drill on the VPS against the latest nightly dump.
- Runbooks: `docs/runbooks/backup-restore.md` and `docs/runbooks/watchdog.md`.

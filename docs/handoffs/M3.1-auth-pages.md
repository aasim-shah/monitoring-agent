## Summary

People can sign up, verify their email, sign in, reset a password, set up or verify two-factor authentication, and accept invitations in the browser. Next middleware sends visitors without a session cookie to `/login?next=…`; the `next` target is validated against open redirects.

## Delivered

| Route / file | Behavior |
|---|---|
| `/login` | Validated form; on success goes to `next` or `/mfa?next=…` when a second factor is required; "Continue with Google" shown only when `NEXT_PUBLIC_GOOGLE_LOGIN=1` |
| `/signup` | Creates the account; always shows "check your email" (the API never reveals existing accounts) |
| `/verify?token=` | Verifies once on load (single-use guard under React Strict Mode) |
| `/reset` and `/reset?token=` | Request link; choose new password (other sessions signed out) |
| `/mfa` | Enroll (setup key + otpauth link → code → recovery codes shown once) or verify (code or recovery code) |
| `/invitations/accept?token=` | Accepts and opens the organization; unauthenticated visitors are sent to login and back |
| `middleware.ts` | Public: `/login`, `/signup`, `/verify`, `/reset`; everything else needs the `pcp_session` cookie (API still validates it) |
| `lib/safe-next.ts` | Accepts only same-origin relative paths; rejects `//host`, backslashes, schemes, control characters, percent-encoded variants |
| `components/auth/` | `LoginForm`, `SimpleForm` (generic validated form), `AuthCard` |
| `lib/use-once.ts` | Runs single-use token effects exactly once |
| `next.config.mjs` | `API_INTERNAL_URL` rewrites `/api/*` for `next dev` (Compose uses Caddy) |
| `app/page.tsx` | `/` → `/orgs` |

- No QR code yet; the setup key and `otpauth://` link work with every authenticator app.

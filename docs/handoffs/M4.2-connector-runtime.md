## Summary

`@pcp/connector-runtime` is the only way platform code runs a connector. It loads the connection inside the caller's tenant (RLS) and product scope, decrypts credentials, runs the operation, maps the outcome onto the lifecycle, records health, and redacts credential values from every error it returns or stores.

## Delivered

| Export | Behavior |
|---|---|
| `storeCredentials(tx, ctx, connectionId, credentials, keyRing)` | Envelope-encrypts the credentials JSON with AAD `"<organizationId>:<connectionId>"` into `connection_secrets` (upsert; sets `rotated_at` on replace) |
| `decryptCredentials(...)` | Reverse; fails if the ciphertext was moved to another row |
| `ConnectorRuntime.validate(ctx, id)` | ok → `connected` (or `recovered` from degraded); missing permissions → `degraded` + `permission_denied`; connector errors → `degraded` + reason; rate limited → status kept, reason `rate_limited` + `retryAfterSeconds`; disconnected/revoked never revived; writes `connection_health` |
| `ConnectorRuntime.discover(ctx, id)` | Discovery page from the connector |
| `NotFoundError` | Other tenant, or product-scoped caller without a resource scope on one of their products |

Credentials are decrypted before every operation, so corrupted or misplaced ciphertext always surfaces as `reauthorization_required`.

## Decisions

- Eager decryption (see summary) instead of lazy, found by the tamper test.
- The whole-database scan reads every row as JSON through SQL instead of running `pg_dump`; it covers the same data without needing a client binary in CI.

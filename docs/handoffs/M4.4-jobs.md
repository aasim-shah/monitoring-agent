## Summary

`@pcp/jobs` runs connection work in the background: BullMQ queues with deterministic job IDs, processors that call the connector runtime and record every run, dead letters after five attempts, and a reconciler that keeps BullMQ's schedulers equal to the schedules stored in PostgreSQL. The worker app now runs all of it.

## Delivered

| Export / file | Behavior |
|---|---|
| `jobId(kind, org, entity, window?)` | `kind__org__entity[__window]` (BullMQ forbids `:`) |
| `createQueues(redisUrl, { backoffMs? })`, `enqueue(queues, kind, payload)` | Queues `connection-validate`, `connection-discover`; 5 attempts, exponential backoff from 10 s; completed jobs are removed (the same ID can run again later), queued duplicates are ignored |
| `startProcessors({ redisUrl, prisma, runtime })` | Creates a `sync_runs` row (running → succeeded/failed/cancelled); skips deleted or disconnected connections; final failure → `job_executions.status = 'dead_letter'` with the redacted error; success also recorded |
| `reconcileSchedules(schedulerPrisma, queues)` | Reads `pcp_due_job_definitions()` as `pcp_scheduler`; upserts `schedule-<definitionId>` schedulers, removes stale ones |
| `@pcp/connector-runtime` `buildRegistry(env)` | Production connectors (none yet); the mock only with `PCP_ENABLE_MOCK_CONNECTOR=1`, and refused when `NODE_ENV=production` |
| `apps/worker` | Config adds `DATABASE_URL`, `SCHEDULER_DATABASE_URL`, `RECONCILE_EVERY_SECONDS` (60), `MASTER_KEY`; starts processors; reconciles at startup and every 60 s; readiness checks PostgreSQL and Redis |

Job payloads carry only `{ organizationId, connectionId, requestId }`.

## Decisions

- `__` job-ID separator (BullMQ throws `Custom Id cannot contain :`).
- `removeOnComplete: true` so revalidation is never blocked by an old completed job, while concurrent duplicates still collapse.

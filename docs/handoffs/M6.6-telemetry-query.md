## Summary

The API is now the only reader of telemetry. Every query to VictoriaMetrics carries the caller's tenant (`extra_label`) and product, plus agent when given (`extra_filters`), so even crafted PromQL cannot reach other tenants or products. Two endpoints feed the host charts and the infrastructure list.

## Delivered

| Piece | Behavior |
|---|---|
| `TelemetryQueryService.query(ctx, q, scope)` | `query_range` with tenant and product/agent filters; 30 s timeout; step raised so ≤ 11,000 points; ranges > 400 days → 400; > 1,000 series → 422 `too_many_series`; range older than 15 days → `completeness: 'partial'` with a retention gap; storage missing/unreachable → 503 `telemetry_unavailable` |
| `planRange` / `toGrid` (`limits.ts`) | Grid aligned to step multiples like VictoriaMetrics (start floored, end ceiled so the newest samples stay); missing steps and NaN → `null`, never 0 |
| `GET /api/v1/agents/:id/metrics?range=15m\|1h\|6h\|24h\|7d` (`telemetry.query`, resource `agent`) | CPU %, memory %, disk % per mountpoint, network in/out bytes/s, `lastSampleAt`, completeness |
| `GET /api/v1/products/:productId/infrastructure` (`telemetry.query`) | Per host: status/stale, current CPU, memory, disk (max mountpoint), last sample time |
| `host-metrics.ts` | Fixed PromQL templates from the verified collector metric names |
| Contracts | `MetricResult` points are `[number, number \| null]`; OpenAPI `MetricPoint` |
| Compose / config | API `VM_QUERY_URL=http://victoriametrics:8428` |
| Tests infrastructure | `@pcp/test-support` `startVictoria()`; API global setup provides `vmUrl` |

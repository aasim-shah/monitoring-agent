## Summary

`@pcp/database` owns the Prisma schema, the first migration (tables + forced RLS + narrow cross-tenant functions), the role bootstrap, and a `pcp-db migrate` CLI. Integration tests prove tenant isolation directly against PostgreSQL 17 in a container.

### Cross-tenant functions (owned by `pcp_rls_definer`, EXECUTE granted only to `pcp_app`)

| Function | Returns |
|---|---|
| `pcp_user_memberships(user)` | That user's memberships (org, name, role, product scope) |
| `pcp_find_invitation(token_hash)` | Invitation row for acceptance |
| `pcp_resolve_product_org(product, user)` | Product's organization if the user is a member, else NULL |
| `pcp_resolve_environment_org(environment, user)` | Same for environments |

## Tests

| Test | Proves |
|---|---|
| RLS enabled and forced on all 7 tenant tables | Policy cannot be skipped by the table owner |
| Each tenant table returns 0 rows without context (7) | No default visibility |
| Each tenant table returns only the current tenant (7) | Isolation |
| Insert of another tenant's row rejected | `WITH CHECK` works |
| Memberships via `pcp_user_memberships` without context | Login/context switching possible without weakening policies |
| `pcp_resolve_product_org` only for members | No organization disclosure to strangers |
| `pcp_app`: no BYPASSRLS, not superuser, owns nothing | D8 |
| `UPDATE`/`DELETE audit_logs` as `pcp_app` denied | Append-only audit |
| `_prisma_migrations` not readable by `pcp_app` | Least privilege |
| Schema drift: migrations equal `schema.prisma` | Generated part stays in sync |

## Decisions

- Product scope on memberships is `all_products` + `product_ids uuid[]`; no separate `role_assignments` table (one role per member covers spec §2.1).
- `SECURITY DEFINER` functions are owned by a dedicated NOLOGIN BYPASSRLS role, because forced RLS would filter functions owned by the table owner.
- `pcp_migrator` gets `CREATE` on the database because `prisma migrate deploy` issues `CREATE SCHEMA IF NOT EXISTS`.

## Known limitations

- `FORCE ROW LEVEL SECURITY` also applies to `pcp_migrator`; future data migrations must set tenant context or run as superuser.
- Emails are stored lowercase by application code; there is no `citext`.

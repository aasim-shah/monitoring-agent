## Summary

`@pcp/tenant-security` provides the role → permission matrix, `can()`, and `withTenant()`. Integration tests prove pooled connections never carry tenant context between borrowers (Review Focus #1).

## Delivered

| Export | Behavior |
|---|---|
| `ROLE_PERMISSIONS` | owner: all 25; admin: all except `action.approve`; operator: view + `agent.enroll`, `pack.manage`, `relationship.verify`, `logs.tail`, `incident.manage`, `action.propose`, `report.manage`, `ai.use`; analyst: view + `ai.use`; viewer: view (`org.view`, `product.view`, `connection.view`, `agent.view`, `asset.view`, `telemetry.query`, `incident.view`, `report.view`) |
| `can(ctx, permission, { productId? })` | Role grant plus product scope for product-scoped members |
| `withTenant(prisma, ctx, fn)` | Interactive transaction; `set_config('app.organization_id', …, true)` and `app.user_id` for user actors; maxWait 5 s, timeout 15 s |

## Tests

| Test | Result |
|---|---|
| Spec §2.1 columns (view, configure connections, manage policies, approve actions, manage members), owner = all, viewer read-only, analyst no writes | pass |
| Product scope: analyst `['p1']` allowed on p1, denied on p2; all-products allowed; no roles → nothing | pass |
| Pool size 1: after `withTenant(A)`, same connection has empty `app.organization_id` and sees 0 products | pass |
| 50 interleaved A/B transactions on a pool of 5 never see the other tenant | pass |
| Error inside `withTenant` leaves the next borrower clean | pass |
| `app.user_id` set for user actors | pass |

## Decisions

- Signature is `withTenant(prisma, ctx, fn)` (the master plan's `withTenant(ctx, fn)` had no way to receive the client).
- Operator "limited" configuration (spec §2.1) maps to agent enrollment and pack management, not connection configuration.

## Summary

Admins create an enrollment token for an environment and get a ready-to-paste install command. A host exchanges that token plus a CSR for its own agent identity and a 30-day client certificate. The tenant scope comes only from the enrollment record.

## Delivered

| Route | Behavior |
|---|---|
| `POST /api/v1/environments/:environmentId/agent-enrollments` (`agent.enroll`) | `{ agentType?, maxUses? 1–1000 (1), expiresInMinutes? 5–1440 (60) }` → 201 `{ id, token, expiresAt, maxUses, installCommand }`. Token `pcp_enr_` + 256 bits; stored as HMAC-SHA-256 with a pepper derived from `MASTER_KEY` (HKDF). Audited. |
| `GET /api/v1/environments/:environmentId/agent-enrollments` (`agent.view`) | Latest 50: type, expiry, uses; never the token or hash |
| `POST /agent/v1/enroll` (`@AgentEnroll()`: no session, no certificate) | Rate limit 10/min/IP. Protocol ≠ `1.0` → 426 `upgrade_required`. Schema (`@pcp/agent-protocol`) → 400. Bad CSR → 400 `invalid_csr` **before** the token is consumed. Token consumed atomically (`pcp_consume_enrollment`); any failure → the same 401 `invalid_enrollment_token`. Creates agent, credential (fingerprint), X25519 key, audit `agent.enrolled`; returns `EnrollResponse` |
| No PKI configured | Both routes → 503 `agent_enrollment_unavailable` |

Supporting code: `tokens.ts` (`EnrollmentTokens`), `settings.provider.ts` (`AGENT_SETTINGS`: CA + task signer or null), `task-signer.ts` (`TaskSigner.publicKeyBase64()`; signing arrives in Task 6), `test/agent-helpers.ts` (dev PKI env, CSR, enroll request, environment and enrollment helpers).

## Decisions

- Environment-scoped route (spec's `POST /api/v1/agent-enrollments` had no tenant in the path); spec §15.3, WB-03 §7, and OpenAPI updated.
- Pepper derived from `MASTER_KEY` instead of a new secret; rotating `MASTER_KEY` invalidates outstanding tokens (all expire within 24 h).

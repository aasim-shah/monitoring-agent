## Summary

The dashboard covers everything the M2 API offers: products with domains and repositories, environments, members with role and product-scope management, invitations, the audit log with paging, and organization settings. Controls a role cannot use are hidden; the API still decides and its errors (`role_above_actor`, `last_owner`, …) are shown inline.

## Delivered

| Route | Content |
|---|---|
| `/orgs/[orgId]` | Product list (domains, environment count); "New product" for `product.manage` |
| `/orgs/[orgId]/products/[productId]` | Name, description, domains, repositories, environments, "Add environment" for `product.manage`; health card states that no data sources exist yet |
| `/orgs/[orgId]/members` | Members (email, scope, role); role change and removal only for roles at or below the viewer's own; invite form with role and optional product scope |
| `/orgs/[orgId]/audit` | Newest first; "Load more" through the API cursor |
| `/orgs/[orgId]/settings` | Name, timezone, data retention days; users without `org.settings.manage` see the not-found state |

Components and helpers: `RoleSelect`, `InviteForm`, `AuditTable`, `CreateProductForm`, `QueryState` (loading / 404 / error / data), `roleCan`, `rolesAtOrBelow`, `splitList`.

Contract update: `GET /api/v1/organizations/{orgId}/audit-logs` now declares `limit` and `before` query parameters in OpenAPI (the typed client required them).

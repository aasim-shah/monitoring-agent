## Summary

`.github/workflows/ci.yml` runs seven jobs on every pull request and every push to `main`. `.github/workflows/nightly-live.yml` runs live-provider tests nightly once connectors add `test:live` scripts. Both pass `actionlint`. The repository is now Prettier-clean, and CI enforces it.

## Delivered

| Job | What it runs |
|---|---|
| `node` | `pnpm install --frozen-lockfile`, `turbo run build lint typecheck test`, `pnpm test:repo`, `pnpm format:check` |
| `go` | `go vet`, `go test`, `gofmt -l` on all Go modules (Go 1.23.12) |
| `openapi` | `pnpm lint:openapi` (Spectral, fail on error) |
| `smoke` | Matrix `managed` / `self_hosted`: Compose smoke suite for that mode plus config and Caddy checks |
| `sbom` | `anchore/sbom-action@v0.24.3`, SPDX JSON artifact |
| `osv-scan` | `google/osv-scanner-action/osv-scanner-action@v2.7.0`, recursive |
| `secret-scan` | `gitleaks/gitleaks-action@v2.3.9`, full history |

Also: `turbo.json` task `test:live` (uncached, passes `LIVE_*` env); root scripts `format`, `format:check`, `test:smoke`, `test:go`, `vet:go`; `scripts/__tests__/ci.test.mjs`.

Actions are pinned to exact release tags within majors whose inputs are known (checkout v4.4.0, setup-node v4.4.0, setup-go v5.6.0). Newer majors exist (checkout v7, setup-go v7); upgrading is a separate task.

## Action required (human)

1. Create the GitHub repository and push `feat/m0-m1-foundation`; open a pull request to see the first CI run.
2. If the repository belongs to a GitHub organization, gitleaks-action needs a `GITLEAKS_LICENSE` secret (free for personal accounts).
3. Add `LIVE_*` secrets when live connector tests exist (M7+).

## Decisions

- Integration (Testcontainers) and agent end-to-end jobs are added by M2 and M6, when those suites exist.
- `actionlint` flag is `-no-color` (the expansion plan's `-color=never` is invalid for 1.7.7).

## Known limitations

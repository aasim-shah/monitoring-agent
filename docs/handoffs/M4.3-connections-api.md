## Summary

The API now manages connections end to end: the catalog lists registered connectors, an admin creates a draft connection, submits credentials (encrypted at rest, never returned), and the worker validates it to `connected`. Discovery lists provider resources, which the admin maps to products. Deleting crypto-shreds the credentials and leaves the connection terminally `disconnected`. This meets the M4 exit gate with the mock connector.

## Delivered

| Route | Permission | Behavior |
|---|---|---|
| `GET /api/v1/connectors/catalog` | session | Type, version, capabilities, locations, credential fields, JSON config schema |
| `POST /api/v1/organizations/:orgId/connections` | `connection.configure` | 201 draft; 400 `unknown_connector`, `unsupported_location`, `validation_failed` (field names only) |
| `GET /api/v1/organizations/:orgId/connections` | `connection.view` | All for org-wide members; product-scoped members see only connections scoped to their products |
| `GET /api/v1/connections/:id` | `connection.view` | Detail plus `hasCredentials`; never the credentials |
| `POST /api/v1/connections/:id/authorize` | `connection.configure` | `{ credentials }` must match the connector's credential fields; stored with AES-256-GCM (AAD `org:connection`); status `pending_validation`; validate job queued |
| `POST /api/v1/connections/:id/validate`, `/discover` | `connection.configure` | 202 `{ jobId }`; 409 `connection_closed` when disconnected/revoked |
| `GET /api/v1/connections/:id/resources` | `connection.configure` | Runs discovery now; connector errors map to 400/409/429 (+`Retry-After`)/502 |
| `POST /api/v1/connections/:id/resource-scopes` | `connection.configure` | Replaces scopes; products and environments must belong to the org (and to the caller's product scope) |
| `GET /api/v1/connections/:id/sync-runs` | `connection.view` | Latest 50 runs; error messages already redacted |
| `DELETE /api/v1/connections/:id` | `connection.configure` | 202; deletes the secret row; status `disconnected` |

Other changes:

- `@TenantScope({ param: 'id', resource: 'connection' })`: the tenant guard resolves the org with `pcp_resolve_connection_org`. Product-scoped members pass only when the connection has a resource scope on one of their products; otherwise 404.
- `ConnectorRuntime.validate` now updates status with `UPDATE … WHERE status NOT IN ('disconnected','revoked')`. This closes a race the API test found: a delete that committed while validation ran was overwritten with `connected`.
- Self-review fixes (test-first): resubmitting credentials while `pending_validation` returned 500 (state machine now allows `pending_validation → auth_completed`); a product-scoped admin replacing resource scopes deleted scopes on products outside their scope (replace now limited to the caller's products).
- OpenAPI: connection paths and schemas (`x-implemented-in: M4`); spec §15.2 lists the org-scoped create/list routes. API client regenerated.
- API dependencies add `@pcp/connector-runtime`, `@pcp/connector-sdk`, `@pcp/jobs`. `@pcp/connectors-mock` stays a dev dependency of the runtime only.

## Decisions

- Resource scopes are not checked against a fresh discovery (the scope rows are labels; the connector re-checks access on every call). Cost if wrong: an admin can scope an external ID the provider does not return.
- Product-scoped admins can create connections at org level but see them only after scoping them to one of their products.

## Summary

`docker compose up` now runs the full platform skeleton: Caddy, web, api, worker, PostgreSQL, Redis, VictoriaMetrics, vmalert, opamp-server, and ingest-gateway, all health-checked. Only Caddy publishes ports. The smoke suite proves the stack becomes healthy in both `managed` and `self_hosted` modes and that bootstrap mode refuses agent, OAuth, and webhook routes.

## How to run

```bash
cp .env.example .env
# set POSTGRES_PASSWORD and REDIS_PASSWORD (openssl rand -hex 32)
docker compose up -d --build --wait
curl http://localhost:8080/healthz      # {"status":"ok","service":"api","deploymentMode":"managed"}
open http://localhost:8080/              # web placeholder
docker compose down                       # add -v to delete volumes
```

## Tests

`pnpm test:smoke` → 8 passed:

| Test | Proves |
|---|---|
| compose refuses to start without POSTGRES_PASSWORD | Missing secrets fail fast with the variable name (Review Focus #2) |
| storage ports are not published; only caddy publishes | Checked through `docker compose config`, not host probing, so local services cannot cause false failures (Review Focus #1) |
| stack becomes healthy in managed / self_hosted | `up --wait` succeeds; `/healthz` via Caddy returns the right `deploymentMode`; web serves `/` |
| bootstrap mode refuses agent, OAuth, and webhook routes | 503 on `/agent/v1/enroll`, `/webhooks/github/x`, `/api/v1/oauth/google/callback` |
| caddy configs validate (bootstrap, production) | Both Caddyfiles pass `caddy validate`; production with a generated test CA |

First run builds all images (~6 min); later runs reuse the cache (~40 s per mode).

## Decisions

- The `migrate` one-shot service is added in M2.1, when the Prisma schema exists.
- Caddy health check uses its local admin endpoint (`127.0.0.1:2019`), which works in both configs.
- The api health check uses `/readyz`, so the api only becomes healthy after PostgreSQL and Redis respond.
- `BOOTSTRAP_MODE` is passed to Node services now; API-side enforcement lands with the routes (M5, M7, M13). The edge already refuses those routes.

## Known limitations

- The production config needs `agent-ca/chain.pem`; Caddy will not start in production mode without it (intended).
- Secrets must be URL-safe because they are embedded in connection URLs (`.env.example` recommends hex).

## Summary

Tenant mutations write an audit entry in the same transaction as the change, so a change cannot commit without its record. Owners and admins read the log through a paged, tenant-scoped endpoint. The application role cannot update or delete entries (enforced in PostgreSQL since M2.1).

## Delivered

| Path | Purpose |
|---|---|
| `src/modules/auditing/audit.service.ts` | `AuditService.record(tx, ctx, event)`; `list(ctx, { limit, before })` newest first with an opaque `(createdAt, id)` cursor |
| `src/modules/auditing/audit.controller.ts` | `GET /api/v1/organizations/:orgId/audit-logs?limit=1..100&before=<cursor>` (`audit.view`; default limit 50) → `{ entries, nextBefore }` |
| `src/modules/auditing/auditing.module.ts` | Global module exporting `AuditService` |
| Services updated | Organizations: `organization.created`, `member.owner_created`, `organization.settings_updated`; products: `product.created`, `environment.created` |

Each entry stores actor type and ID, action, target type and ID, metadata (names and changed field names, never values of secrets), and the request ID.

## Decisions

- Audit writes are explicit calls inside each service transaction, not an interceptor, so entries cannot be written for changes that roll back.
- `apps/api` no longer emits `.d.ts` files (`declaration: false`); the app is not a library, and declaration emit forced annotations on every Prisma-returning method.

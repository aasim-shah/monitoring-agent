## Summary

Owners and admins invite people by email with a role and optional product scope. Invitees accept with a single-use, 7-day token while signed in as the invited address. Members can be re-scoped or removed, never above the actor's own role, and the last owner can never be removed or demoted. Every step is audited.

## Delivered

| Route | Permission | Behavior |
|---|---|---|
| `POST /api/v1/organizations/:orgId/invitations` | `org.members.manage` | `{ email, role, productIds? }` → 201 `{ id, email, role, expiresAt }`; emails an accept link; token stored as SHA-256; product IDs must belong to the organization |
| `POST /api/v1/invitations/accept` | session only | `{ token }` → 200 `{ organizationId, role }`; 400 `invalid_token` (unknown, used, expired); 403 `email_mismatch`; 409 `already_member` |
| `GET /api/v1/organizations/:orgId/members` | `org.view` | `{ members: [{ id, userId, email, role, productIds, createdAt }] }` |
| `PATCH /api/v1/organizations/:orgId/members/:memberId` | `org.members.manage` | `{ role?, productIds?: uuid[] \| 'all' }`; 403 `role_above_actor`; 409 `last_owner` |
| `DELETE /api/v1/organizations/:orgId/members/:memberId` | `org.members.manage` | 204; 403 `role_above_actor`; 409 `last_owner` |

Role rank: owner 5 > admin 4 > operator 3 > analyst 2 > viewer 1. Audit actions: `invitation.created`, `member.joined`, `member.updated`, `member.removed`.

Files: `src/modules/members/{members.controller,members.service,roles,schemas,members.module}.ts`.

## Decisions

- One error code, `role_above_actor`, covers invitations and member changes (the plan's `role_above_inviter` merged into it).
- Test helpers now send bodiless requests without `content-type`, as browsers do; Fastify rejects an empty body declared as JSON.
- Test IPs are random, because test files run in parallel against one Redis and shared counters tripped rate limits.

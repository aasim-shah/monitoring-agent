## Summary

The API now authenticates people: email/password sign-up with verification, login, logout, password reset, TOTP MFA with recovery codes, and Google sign-in (identity scopes only). Server-side sessions sit in an HttpOnly cookie. Every non-public route requires a session, enforces MFA, and rejects cross-origin writes.

## Delivered

| Path | Purpose |

### Endpoints and responses

| Route | Success | Errors |
|---|---|---|
| `POST /api/v1/auth/signup` | 202 `{status:'accepted'}` (same for existing emails) | 400 `validation_failed` (password < 12), 429 |
| `POST /api/v1/auth/verify` | 204 | 400 `invalid_token` |
| `POST /api/v1/auth/login` | 200 `{mfaRequired}` + cookie | 401 `invalid_credentials` (same for unknown email), 403 `email_not_verified`, 429 `rate_limited` + `Retry-After` |
| `POST /api/v1/auth/logout` | 204 | 401 |
| `POST /api/v1/auth/mfa/enroll` | 200 `{secret, otpauthUri}` | 409 `mfa_already_enabled` |
| `POST /api/v1/auth/mfa/verify` | 200 `{recoveryCodes}` on activation, else `{status:'verified'}` | 401 `invalid_mfa_code`, 400 `mfa_not_enrolled`, 429 |
| `POST /api/v1/auth/password/reset-request` | 202 (same for unknown emails) | 429 |
| `POST /api/v1/auth/password/reset` | 204 (revokes all sessions) | 400 `invalid_token` |
| `GET /api/v1/auth/google/start` | 302 to Google | 404 `google_login_not_configured` |
| `GET /api/v1/auth/google/callback` | 302 to app + cookie | 400 `invalid_state`, 401 `invalid_id_token`, 403 `google_email_unverified`, 502 |
| `GET /api/v1/me` | 200 `{user, memberships, session:{mfaVerified}}` | 401 `unauthenticated` |

Rate limits: 10 requests/min/IP for each of signup, login, MFA verify, password reset (Redis, shared across replicas). Client IP comes from `X-Forwarded-For` set by Caddy (`trustProxy`).

## Tests

`auth.int.test.ts` (15) and `google-login.int.test.ts` (5), all passing. Covered: identical sign-up responses for new/existing email; short password rejected; verification single use; unverified login refused; wrong password vs unknown email identical; 11th login from one IP → 429 with `Retry-After`; cookie flags with and without bootstrap mode (Review Focus #4); logout; foreign `Origin` → 403; `/me` needs a session; identical reset responses; reset revokes old sessions; MFA enrollment encrypts the secret and returns 10 codes; next login needs a second factor; wrong code → 401; recovery code works exactly once. Google: only `openid email profile`, PKCE S256, state; wrong state → 400; unverified email → 403; valid token → verified user and session; unconfigured → 404.

## Decisions

- Google sign-in that links to an existing account whose email was never verified discards that account's password and revokes its sessions (account pre-hijacking defense, found in final review). Linking to a verified account keeps its password.
- Without `SMTP_URL`, the mailer does not send and logs only the subject (bodies contain tokens). Self-hosted and managed deployments must configure SMTP before inviting users.
- Login requires a verified email.
- `/readyz` now sets its 503 status directly instead of throwing, so the global error filter formats only real errors.
